전체 교체 vs Virtual DOM Patch

메인 데모의 성능 실험 부분만 따로 뽑은 독립 페이지입니다. 같은 변경을 `전체 교체`와 `Diff + Patch` 두 방식으로 여러 번 반복 실행해 평균 시간을 비교합니다.

비교 대상

전체 다시 그리기 vs Virtual DOM Diff + Patch

핵심 메시지

Virtual DOM이 항상 더 빠른 것은 아니며, 상황에 따라 다릅니다.

실험 방식

숨겨진 전용 DOM 루트에서 같은 시나리오를 반복 측정합니다.

성능 실험

4개 테스트 케이스를 직접 실행해보세요

작은 DOM에서는 차이가 거의 없을 수 있고, 큰 DOM에서 일부만 바뀌면 Patch가 유리할 수 있습니다. 반대로 변경 범위가 넓으면 전체 교체가 더 빠를 수도 있습니다.

성능 테스트 대기 중

테스트 설명

아직 실행한 테스트가 없습니다.

최근 성능 결과

실행된 케이스 기록

    읽는 법

    발표에서는 이렇게 설명하면 좋습니다

    이 수치는 절대적인 진리가 아니라, 어떤 상황에서 어떤 전략이 유리한지 보여주는 실험값입니다.

    1. 부분 변경이 적을 때

    긴 리스트에서 텍스트 1개, class 1개만 바뀌면 Patch가 유리할 수 있습니다.

    2. 추가/삭제가 작을 때

    항목 1개만 추가되는 상황은 전체 재렌더링보다 CREATE Patch가 효율적일 수 있습니다.

    3. 대량 변경일 때

    대부분이 바뀌면 Diff 계산 비용이 커져 전체 교체가 더 빠를 수도 있습니다.

    개발자 도구 콘솔을 열면 각 케이스의 평균 시간과 승패가 표 형태로 함께 출력됩니다.
